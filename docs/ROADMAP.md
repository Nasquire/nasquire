# Nasquire 로드맵
> 공개 문서. 내부 환경 정보는 넣지 않는다.

## 목표
- 기존 폴더(NAS 공유·로컬)를 읽기 전용으로 감시 → 텍스트 추출 → 키워드(BM25, Nori)+벡터 혼합 색인 → 검색 API·MCP 도구로 제공.
- MCP 도구: `search_documents`(조각+경로+쪽), `get_document`(범위 텍스트), `download_file`(짧은 유효 주소). 기본 읽기 전용.
- 근거 위치: PDF 쪽, PPT 슬라이드, Excel 시트·행, Word 제목·문단.
- 로그인: 첫 실행 때 관리자 생성(비밀번호+TOTP 선택). 클라이언트별 API 토큰(한 번만 표시·해시 저장·만료·소스 범위·읽기/쓰기·감사 로그).

### 판단한 것

- MCP는 **공식 Java SDK 2.1.0의 Servlet stateless Streamable HTTP**를 선택했다. Spring AI 전체 모델/오케스트레이션 계층이 불필요한 두 읽기 도구라 직접 SDK가 의존성과 설정을 줄인다. 서버는 매 HTTP 요청의 인증 문맥을 도구 호출에 전달하고 항상 소스 범위를 재검사한다. 세션 ID/상주 SSE 연결 없이 POST JSON 응답을 사용한다. `/mcp`의 관리자 세션 단독 접근은 금지하며 Origin 헤더는 명시한 허용 목록만 받는다.
- H2는 내장 파일 DB로 사용하며 MPL-2.0 옵션을 선택했다. ICU는 Unicode-3.0, 나머지 주요 런타임은 Apache-2.0/MIT이다. Jakarta Annotations의 GPL + Classpath Exception 옵션을 포함하여 `THIRD-PARTY.md`에 정리했다. Logback 대신 Apache Log4j2를 사용했다. 루트 LICENSE·LICENSE-EXCEPTIONS.md·NOTICE는 변경하지 않았다.
- 1단계에서는 TOTP를 생략했다. 미구현 기능/배포 검증은 아래 후속 목록에 남긴다.
- 재시작 시 소스별 색인을 재구축한다. mtime/크기를 모두 보존하는 변경은 재색인 버튼으로 반영한다. 자동 색인 상태는 파일 수이며 검색 결과 수는 조각 수다.

### 512 MiB 근사 실측

- 자체 작성 Markdown 20개(한국어/영문, 각 60문단), 2쪽 PDF 20개(영문), 합계 40파일/40 PDF쪽.
- JVM: `-Xms64m -Xmx256m -XX:+UseSerialGC -XX:MaxMetaspaceSize=128m -XX:ReservedCodeCacheSize=48m -Xss512k -XX:MaxDirectMemorySize=32m`.
- Lucene RAM buffer 8 MiB, H2 연결 최대 2, Tomcat 최대 16스레드. PDF 텍스트는 쪽마다 처리하고 PDFBox scratch는 디스크를 사용한다.
- 최종 실행의 **시작 중 최대 RSS 161.8 MiB, 색인/검색 중 최대 RSS 228.4 MiB**(233884 KiB). Linux `/proc`에서 **애플리케이션 JVM만** 50ms 간격으로 측정했다. Gradle·Node 빌드 프로세스는 런타임 측정에 포함하지 않았다.
- 한국어 질의 80조각, PDF 영문 질의는 2쪽 결과 20개, 추가 검색 30회, MCP 초기화·도구 목록·두 도구 호출·토큰 폐기를 검증했다. 실행 스크립트 종료 코드 0.
- **Spring Boot 유지 의견:** 이번 소형 문서 MVP는 512 MiB 목표에 충분한 RSS 여유가 있어 유지한다. 실제 cgroup 제한, 파일 캐시·컨테이너 전체 사용량, 큰 PDF·대규모 소스·동시 요청에 대한 보장은 아니므로 배포 전 별도 부하 검증이 필요하다.
- 상세: `docs/verification/mvp.md`. 재현: `VERIFY_PORT=8101 python3 scripts/verify-runtime.py`. 원시 결과는 무시되는 `build/verification/`.

### 판단한 것

- 자동 다운로드 대상은 데이터 디렉터리 내부로 제한하여 원본 소스 쓰기를 차단했다. 외부 경로에 사전 준비한 모델은 읽기만 한다.
- E5 전용 ONNX 구조·384차원·256토큰 제한을 사용한다. 임의 구조 모델 지원은 범위를 넓히지 않았다. 내장 배치는 1, 원격 기본 배치는 2다.
- 원격 모델 이름이 같아도 서버에서 실제 가중치를 바꾸면 자동 감지가 불가능하다. 관리자 재색인이 필요하다. 원격 키·배치·타임아웃만 바꾸면 모델 식별자를 바꾸지 않는다.
- 색인 작업과 공급자 교체·검색을 직렬화하여 차원 혼합과 닫힌 공급자 사용을 방지한다. 큰 파일이나 느린 공급자는 검색 지연을 늘릴 수 있다.
- 기능 구현은 끝났지만 내장 512 MiB 목표는 미완료다. 상세 실측·검증 명령·실패 이력은 `docs/verification/vector.md`, 설정은 `docs/embeddings.md`에 기록한다.

### 판단한 것

- 객체 모델의 메모리 증가를 제한하려고 Office/HWP 원본은 설정 파일 상한과 별도로 8 MiB 이하, ZIP 항목 1024개·개별 해제 8 MiB·전체 해제 16 MiB·압축률 1% 이상을 적용한다. XML 깊이 64·항목별 노드 100000, HWP는 전체 해제 2 MiB·레코드 깊이 64, 추출 근거 단위 4096개를 제한한다. 초과 파일은 오류로 남기고 재시도한다. Office/HWP 문자 상한에서는 앞부분만 색인한다. 일반 파일 크기 상한 초과도 이제 오류 수에 포함한다.
- XLSX는 전체 워크북 객체를 만들지 않는다. SAX와 읽기 전용 공유 문자열 테이블을 사용하며 공유 문자열/스타일은 위 ZIP 상한 내에서 메모리에 둔다. XLS는 HSSF 이벤트 모델과 SST를 사용한다. 수식은 저장된 결과를 읽고 실행하지 않는다.
- `location`에 PDF page, PPT slide, Excel sheet·rowFrom/rowTo, Word/HWP paragraph·선택 heading을 보존한다. 기존 `page`는 호환용이며 새 형식은 추출 순서다. 문단 쪽수를 추정하지 않는다. 표·도형 안 텍스트는 소속 문단/슬라이드의 근거를 공유한다.
- 다운로드 링크는 소스 범위를 검사한 뒤 발급하는 짧은 수명의 접근 권한이다. 보안 검토 반영 후 발급 토큰 폐기·만료·범위 축소를 수신 때 검사하며 만료 또는 재시작 때 무효화된다. 소스 삭제·제외 규칙 변경·링크 탈출은 수신 때 다시 검사한다. 다운로드는 내부 링크까지 포함해 심볼릭 링크를 모두 거부한다. Linux SecureDirectoryStream 미지원 파일시스템은 안전하게 실패한다. 파일 교체 시 최신 원본을 받는 주소이며 내용 버전 고정/업로드/외부 공유 기능은 아니다.
- 보안 검토 반영 후 공개 주소를 설정하지 않으면 상대 경로를 반환하며 역방향 프록시 환경은 `nasquire.public-url` 명시를 권장한다. URL의 쿼리에는 짧은 접근 권한이 있으므로 운영 프록시 접근 로그에서도 쿼리를 저장하지 않도록 구성한다. 앱 감사에는 작업·행위자·상태만 기록한다.

### 검증 중 수정·남은 한계

- 익명 위조 링크 거부가 Spring Security에서 401로 표현된 첫 통합 테스트는 실패했다. API 예외 처리에서 접근 거부를 403으로 명시하고 통과했다. 최초 런타임도 새 DOC의 `Second` 문단이 기존 PDF 전용 결과 수 검사에 포함되어 실패(종료 코드 1)했다. 검증을 PDF 경로로 한정한 뒤 동일 명령이 통과했고 실패 실행도 서버·포트를 정리했다.
- [ ] 실제 Word/PowerPoint/Excel/HWP 편집기에서 생성 샘플의 열기/렌더링 검증. 추출과 색인 왕복은 검증했지만 전체 문서 구조 호환성 검증은 아니다.
- [ ] 암호화 DOC/PPT/HWPX의 실제 편집기 생성 파일 회귀 자료는 미준비. 암호화 DOCX/PPTX/XLSX·XLS와 HWP 암호 플래그, 전체 8형식 손상 파일은 검증했다.
- [ ] 큰 공유 문자열 테이블·복잡한 도형/중첩 표·악성 바이너리 전반의 퍼징과 실제 512 MiB 컨테이너 부하 검증. 파서의 모든 메모리 위험을 작은 샘플 실측만으로 보장하지 않는다. 내장 임베딩의 기존 512 MiB 초과 문제도 그대로 남는다.

### 판단한 것

- 기본 끔은 업로드 소스가 전혀 없는 상태다. 관리자가 별도 폴더를 `upload`로 등록할 때만 쓰기 경로가 열리며 일반 소스 마운트는 계속 읽기 전용이다. API 토큰의 읽기/쓰기 권한 확장은 하지 않았다.
- Java SecureDirectoryStream에는 mkdirat·덮어쓰기 없는 원자적 rename이 없어 Java 25 FFM의 Linux libc 호출로 보완했다. 절대경로의 각 부모를 O_DIRECTORY|O_NOFOLLOW로 고정한다. amd64/arm64의 플래그 차이를 구분하며 다른 플랫폼은 안전하게 실패한다. 폴더를 데이터 폴더에서 이동하는 초기 방안의 파일시스템 간 제약을 제거했다.
- 공개 비밀번호는 브라우저 HTTP Basic 인증 창으로 받는다(사용자명 무시). 별도 공유 세션/관리 쿠키를 만들지 않으며 모든 요청에서 검증한다. 보안 검토 반영 후 실패 횟수는 공유+IP 단위로 보존한다. 기본 IP 제한은 연결 주소를 사용하고 명시한 신뢰 프록시에서만 전달 주소를 사용한다.
- 공유는 경로와 생성 시 파일 식별자를 묶으며 내용 버전을 고정하지 않는다. 전송 시작 전 횟수를 소비하여 동시 요청도 상한을 넘지 않는다. 중단 전송도 횟수에 포함한다. 폴더 목록은 요청당 최대 1000개다.
- 상세 실측·실패 이력·운영 한계는 [업로드·공유 검증](verification/upload-share.md)에 기록한다. 기존 1~3단계 판단·내장 임베딩의 512 MiB 초과는 변경하지 않는다.

- 소스 등록 해제 시 휴지통 메타데이터를 제거하고 공유를 철회한다. 숨김 휴지통 실제 파일은 보존하므로 등록 해제 전에 복원/정리해야 한다. 프록시에서 공유 토큰 경로·Authorization·티켓 쿼리를 로그에 남기지 않는다.
