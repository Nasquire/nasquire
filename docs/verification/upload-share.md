# 3.5단계 업로드·외부 공유 검증

2026-10-24. Linux amd64, 키워드 모드(`embedding=off`). 공개 기록에는 장비·계정·로컬 절대 경로·인증값·공유 원문을 포함하지 않는다.

## 확인한 동작

- 기존 DB 소스의 기본 종류는 `directory`다. 관리자가 별도 쓰기 가능 폴더를 `upload`로 등록한 경우에만 쓰기 API가 작동한다. 소스/데이터 중첩과 업로드/다른 소스 중첩을 양방향으로 거부하며 등록 후 종류·경로 변경도 거부한다.
- 일반 소스 쓰기·관리 세션의 CSRF 없는 변경·API 토큰의 쓰기를 403으로 거부한다. MCP 도구 목록은 기존 세 읽기 도구를 유지한다.
- multipart 임시 파일은 데이터 폴더에 threshold 0으로 저장한다. 파일 상한은 `nasquire.upload-max-bytes`, HTTP 전체 요청 상한은 해당 값+1 MiB다. 서비스도 64 KiB 버퍼로 복사하며 독립적인 누적 크기 상한을 적용한다. 완성 전 파일은 `.nasquire-*.part`이며 원자적 이동 후에만 최종 이름으로 나타난다.
- HTTP 상한 초과는 413이고 기존 파일 내용은 유지된다. 서비스 상한 실패 시 임시 파일을 제거한다. 기본 덮어쓰기 거부·명시적 덮어쓰기 성공·RENAME_NOREPLACE의 기존 대상 보존을 확인했다.
- `../`·절대경로·정규화 전 중간 `..`·NFD·예약 이름·내부 예약 폴더·소스 밖 디렉터리 링크에 대한 업로드를 거부한다. 링크 아래 폴더 생성도 거부한다. 파일/각 디렉터리는 NOFOLLOW로 열며 일반 소스에 쓰기 함수를 적용하지 않는다.
- 폴더 생성·파일 이동·숨김 휴지통 이동·원래 경로 복원·만료 정리를 확인했다. 휴지통/임시 파일은 소스 glob의 기본 제외 대상이다. 등록 해제는 파일을 지우지 않는다.
- 업로드 후 색인을 즉시 예약하고 curl 검색으로 고유 단어를 확인했다. RSS 실측 중 16 MiB 바이너리도 실제 multipart 업로드했다. 바이너리는 검색 형식이 아니므로 색인 문서에는 포함하지 않는다.
- 파일/폴더 공유 생성·폴더 하위 목록·원본 일치 다운로드·상위/절대/NFD 경로 거부·심볼릭 링크 탈출 거부·횟수 소진 404·철회 404·대상 삭제/제외 404를 확인했다. 공개 HTML에 소스 ID·실제 루트 경로를 넣지 않는다.
- 테스트 시계로 만료 경계와 비밀번호 실패 1/2/4/8초 지연·5회 후 15분 제한·대기 후 정상 비밀번호 성공을 확인했다. 실제 HTTP에서 Basic 비밀번호 요청/성공을 확인하고 관리 쿠키만으로 비밀번호를 우회하지 못함을 검증했다. 공개 응답은 Set-Cookie를 생성하지 않는다.
- 다운로드 횟수는 DB 조건부 증가로 전송 전에 예약한다. 공개 페이지는 관리 세션과 분리된 stateless 보안 체인을 사용하며 검색/MCP를 노출하지 않는다. CSP·nosniff·no-referrer·no-store·DENY 헤더를 확인했다.
- IP별 요청 제한의 실제 HTTP 429와 단위 호출의 시간 창 초기화·4096항목 상한·가득 찬 상태의 신규 IP 거부·만료 후 회복을 확인했다. 임의 전달 IP 헤더는 사용하지 않는다.
- 공유 토큰 원문은 생성 응답 이후 목록·감사 로그에 나타나지 않는다. DB는 SHA-256만 가지며 비밀번호는 BCrypt 비용 12다. 공유 생성/철회/열람/다운로드/실패/속도 제한 로그에는 원문 토큰·비밀번호를 기록하지 않는다.

## 안전한 폴더 생성과 원자적 이동

Java SecureDirectoryStream은 읽기/채널 생성/삭제/이동을 제공하지만 안전한 mkdirat와 덮어쓰기 없는 원자적 이동은 제공하지 않는다. Java 25 FFM으로 Linux libc `openat`·`mkdirat`·`renameat2`·`close`를 호출하여 부모 경로의 모든 요소를 NOFOLLOW로 연다. 새 폴더는 0700, 덮어쓰기 없는 이동은 RENAME_NOREPLACE를 사용한다. 소스 내 임시 파일을 사용하므로 데이터 폴더와 다른 파일시스템에서도 파일 업로드 시 파일시스템 간 rename은 필요하지 않다.

amd64/arm64 플래그 차이는 [Linux 공통 UAPI](https://github.com/torvalds/linux/blob/master/include/uapi/asm-generic/fcntl.h)와 [arm64 UAPI](https://github.com/torvalds/linux/blob/master/arch/arm64/include/uapi/asm/fcntl.h)에 맞춰 구분한다. Linux amd64 로컬 실행만 확인했다. Java native access 허용 옵션이 필요하며 bootRun·테스트·기존 Docker 설정에 포함되어 있다. 미지원 플랫폼/파일시스템/시스템 호출은 안전하게 실패한다. 신규 패키지 의존성이나 배포 라이선스 파일 변경은 없다.

## 실패 이력·미검증·운영 위험

- 첫 새 통합 검증은 선택 boolean 필드 생략 시 JSON 역직렬화가 400을 반환하여 기대한 403과 달랐다(`:app:test`, 종료 코드 1; 재실행도 같은 원인으로 1). 선택 필드를 nullable로 처리했다.
- 다음 검증은 기존 설정의 multipart 비활성화 때문에 파일 파트가 인식되지 않아 400으로 실패했다(`:app:test`, 종료 코드 1). multipart를 켜고 디스크 저장을 설정한 뒤 통과했다.
- HTTP 크기 상한 회귀 테스트를 추가한 전체 빌드는 업로드 초과 예외가 기존 상태 충돌 처리에 잡혀 409를 반환해 실패했다(`build`, 종료 코드 1). 413 전용 처리를 추가한 최종 빌드는 0이다. 이 실패들에서 원본 쓰기·외부 공유 범위 우회는 없었다.
- Docker가 없어 실제 512 MiB cgroup·비루트 볼륨·파일 캐시 포함 메모리를 검증하지 않았다. arm64 실기·실제 NAS/NFS/SMB·서로 다른 파일시스템 구성·동시 대용량 부하/디스크 고갈도 미검증이다.
- 실제 브라우저의 한/영·모바일·접근성·Basic 인증 창은 미검증이다. TypeScript/Vite와 HTTP 수준만 확인했다. 목록은 요청당 1000개 상한이며 페이지 나누기는 후속 개선이다.
- 정전/프로세스 강제 종료 시 파일 이동과 H2는 하나의 트랜잭션이 아니다. 임시 파일 또는 미완료 휴지통 메타데이터가 남을 수 있다. 휴지통 메타데이터는 이동 전에 남기며 운영자가 원본과 메타데이터를 점검해야 한다. 숨김 임시 파일의 재시작 자동 정리는 미구현이다.
- 업로드 소스는 앱 전용 권한으로 관리하고 일반 소스는 읽기 전용 마운트를 유지한다. 외부 프로세스의 동시 경로 재배치/교체 스트레스·퍼징은 미검증이다. 심볼릭 링크는 내부 대상도 포함해 거부한다.
- 업로드 소스 등록 해제 후 휴지통 자동 정리/복원은 중단한다. 원래 소스/메타데이터를 유지한 상태에서 복원하고 등록 해제한다. 새로운 소스 ID로 재등록해도 기존 휴지통 메타데이터는 자동 연결하지 않는다.
- 비밀번호 실패 지연은 링크 단위이므로 공격자가 공유 링크의 정상 방문도 잠시 지연시킬 수 있다. IP 제한은 연결 주소 기준이므로 프록시 뒤 방문자가 한도를 공유한다. 4096개 활성 IP 창이 차면 새 IP는 만료까지 429다.
- 공유는 파일 내용 버전을 고정하지 않는다. 전송 시작 시 횟수를 소비하여 중단된 전송도 포함한다. 앱 감사 로그에 비밀값을 남기지 않지만 운영 프록시의 공유 경로/Authorization/서명 쿼리 로그 제외는 배포 설정이 필요하다.

원시 아티팩트: 무시되는 `build/verification/measurement-off.json`, `smoke-off.txt`, `bootrun-off.log`, `build/verification-upload-share-run.txt`, `build/verification-upload-share-final.txt`. 최종 빌드 로그는 `build/upload-share-build-final.log`, 테스트 보고서는 `app/build/reports/tests/test/`, `core/build/reports/tests/test/`다. 원시 로그에는 로컬 정보가 있을 수 있어 공개 문서에 복사하지 않는다.
